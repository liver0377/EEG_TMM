# EEG_TMM 协作与同步指南

## 基本原则

本项目将代码、源数据和实验产物分开管理：

- 远程 Git 仓库是代码、配置、split、manifest 和小型汇总结果的唯一可信来源；
- `/root/fsas/dataset_eeg/unpacked/datasets` 是历史数据和材料来源，默认只读；
- `/root/fnvme/cid_revision` 是新工作区、缓存和实验产物所在的高速存储；
- 原始数据、checkpoint、embedding、生成图和日志不进入普通 Git。

## 多实例协作

每个人、每个实例使用独立 clone。禁止两个人或两个实例共同操作同一个 working tree。

推荐结构：

```text
/root/fnvme/cid_revision/
├── workspaces/
│   ├── wudawei/<instance>/EEG_TMM/
│   ├── fanhao/<instance>/EEG_TMM/
│   └── linxuanqiang/<instance>/EEG_TMM/
├── staged_data/
├── pretrained/
├── cache/
└── artifacts/
    ├── wudawei/
    ├── fanhao/
    └── linxuanqiang/
```

当前 clone 位于：

```text
/root/fnvme/cid_revision/workspaces/wudawei/EEG_TMM
```

## 分支约定

`main` 只保存经过检查的可复现代码。实验分支使用：

```text
exp/<负责人>/<简短任务名>
```

例如：

```text
exp/wudawei/prior-comparison
exp/wudawei/efficiency
```

常规流程：

```bash
git switch main
git pull --ff-only
git switch -c exp/wudawei/prior-comparison

git status --short
git add <明确文件>
git commit -m "feat: add CLIP prior extraction"
git push -u origin exp/wudawei/prior-comparison
```

通过 Pull Request 合入 `main`。不同实例之间不通过复制目录或 `rsync` 同步代码。

## 数据版本

原始数据不得覆盖。新的预处理必须创建新目录，并在 `manifests/` 中记录：

- 来源版本和样本数量；
- train/validation/test split；
- EEG 通道顺序；
- 频段边界和滤波参数；
- 时间窗及采样率；
- 图像与 EEG 的索引映射；
- 归一化和其他预处理步骤。

大型数据由路径引用，小型 manifest 和 split 文件提交 Git。

## 实验产物

每次正式运行必须使用新的唯一目录：

```text
<owner>/<experiment>/<timestamp>_<instance>_<git-sha>_seed<seed>/
```

至少保存：

```text
config.yaml
command.txt
git_commit.txt
environment.txt
metrics.json
stdout.log
```

正式论文数字只能由保存完整元数据的运行产生。汇总脚本从 `metrics.json` 读取结果，不人工复制原始数字。

## 历史快照

`/root/fsas/dataset_eeg/datasets.tar.part-*` 和 `datasets_parts.sha256` 是历史数据的分卷 tar 快照。它们不是日常同步目标，不得覆盖或删除。需要恢复时，先校验所有分卷，再恢复到新的空目录。

现有历史目录和恢复快照都不作为新实验输出目录。新结果只能写入 `/root/fnvme/cid_revision/artifacts/`。

## 提交前检查

- `git status` 中没有数据、权重、日志或秘密信息；
- 配置不包含个人绝对路径；
- 测试或 smoke test 已通过；
- 新实验目录不会覆盖已有结果；
- split 和 manifest 版本明确；
- 提交信息能够说明一个独立改动。
