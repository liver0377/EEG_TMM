## 4. 已发现的数据质量风险

### 4.1 完全重复的结果

以下历史结果逐项完全一致：

```text
AblationStudy/Results/edge/results.txt
AblationStudy/Results/segmentation/results.txt
```

两者的 CLIP-IQA、MUSIQ、NIQE、MANIQA、PSNR、LPIPS、DISTS、SSIM、FID 全部相同。

以下结果也逐项完全一致：

```text
AblationStudy/noise_random/Results/segmentation/results.txt
AblationStudy/noise_random/Results/segmentation_sam/results.txt
```

可能原因包括：

- 两次评测读取了同一个生成目录；
- embedding 或输出路径被覆盖；
- 复制结果时放错目录；
- 两种方法实际复用了同一输入。

在核对生成图片哈希、评测命令和输入路径之前，这些重复结果不能写入大修回复或论文。

### 4.2 指标与论文表格不统一

历史结果包含 PSNR、SSIM、FID，而修订计划表格使用 DISTS、LPIPS、CLIP-IQA、MUSIQ、MANIQA、NIQE。正式实验必须预先冻结唯一指标集合，并统一：

- 图像色彩空间；
- resize/crop 规则；
- GT 配对方式；
- 指标模型版本；
- batch size；
- 是否对整个测试集取算术平均；
- 失败样本处理规则。

## 6. 多先验实验必须先澄清的公平性问题

修订计划目前写作“生成 embedding，再推理”，但不同 encoder 的 embedding 空间不相同：

- CLIP image embedding；
- DINO visual embedding；
- BLIP/VLM caption embedding；
- EEG-supervised image embedding；
- depth、edge、segmentation 图经过何种 encoder 得到的 embedding。

不能仅因维度相同就直接把不同 embedding 输入同一个 Cog-LoRA。这样可能形成严重的分布外输入，比较的将是“是否碰巧匹配训练 embedding 空间”，而不是先验信息质量。

正式协议需要二选一并在论文中明确：

1. **固定 Cog-LoRA 协议**：所有 prior 先通过同一种冻结 encoder，得到同空间 embedding，仅改变 encoder 的输入内容；
2. **按 prior 重训协议**：每个 prior 使用自己的 encoder/adapter，并以相同预算分别训练 Cog-LoRA。

优先建议固定 Cog-LoRA 协议用于控制变量；DINO、BLIP、VLM 原生 embedding 若要加入，应增加维度与分布匹配 adapter，并明确 adapter 是否训练、训练数据和预算。

GT-CLIP 是使用 GT 图像的 oracle upper bound，不应与可部署方法并列宣称公平，只用于解释性能上限。

## 7. 推荐执行顺序

### 阶段 0：找回并冻结原始端到端基线

必须先获得：

- 正式训练仓库或源码目录；
- 论文最终 Ours checkpoint；
- Static LoRA/No guidance checkpoint；
- 一条可从低光输入生成增强图的命令；
- 一条可从生成目录计算全套指标的命令；
- 原论文结果对应的环境版本。

验收标准：在少量固定测试图上复现历史输出，并在完整测试集上得到与论文足够接近的 Ours 指标。

### 阶段 1：统一运行与评测基础设施

- 所有路径参数化；
- 每次运行建立唯一目录；
- 自动记录 commit、seed、配置、环境和输入 manifest；
- 建立统一 restoration evaluator；
- 建立 checkpoint-to-condition manifest；
- 为一张图和一个小 batch 添加 smoke test。

### 阶段 2：多先验比较

建议顺序：

1. Ours；
2. Static LoRA / No guidance；
3. 历史已有的 depth；
4. edge；
5. segmentation；
6. CLIP low-light prior；
7. GT-CLIP oracle；
8. DINO；
9. BLIP caption；
10. VLM caption。

每加入一种 prior，先在相同10张图做 smoke test，确认输入、embedding shape、dtype、归一化和样本顺序，再运行完整测试集。

### 阶段 3：推理效率

在同一 GPU、precision、输入尺寸、batch size、scheduler、prompt 和 I/O 策略下测试：

- SD-Turbo；
- Static LoRA；
- Cog-LoRA。

计时只覆盖模型推理路径，数据读取与保存另行报告。每种方法先 warm-up，再重复测量；CUDA 计时前后必须 synchronize，并报告 latency、throughput 和 peak allocated VRAM。

### 阶段 4：时间窗与 shuffle restoration

这两项依赖 alignment 侧交付，交付物必须包含：

- checkpoint；
- image prior embedding；
- 样本 ID 顺序；
- split 和 preprocessing manifest；
- seed；
- retrieval 指标；
- 训练配置和 commit。

只有在这些交付物齐全后才启动对应 Cog-LoRA，避免配错 embedding 与图像顺序。

### 阶段 5：最新 SOTA

先冻结输入、输出和指标协议，再选择 2025--2026 方法。每个方法优先使用官方代码与官方 checkpoint，保留 commit、配置和许可证信息。该阶段不得与核心基线恢复并行修改同一评测代码。
